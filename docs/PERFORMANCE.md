# v0.1.0 打开速度实测

测试日期：2026-10-12。环境：Windows 11、Intel Core i9-12900KF、约 32 GiB 内存；SE 为 x64 Release、关闭 Open Timing 插桩。测试文件为 183,823,108 字节（175.3 MiB）、96 kHz、16-bit、双声道 PCM WAV，时长 239.353 秒。文件仅在本机测试，不随源码或 Release 分发。

## SE 核心就绪

沿用 `tools/Invoke-CoreOpenBenchmark.ps1` 的 Release 配置与共享内存观察点。核心就绪是可播放和首帧有效波形两者都成立，每个程序先预热一次，再交错打开旧版与最终候选各 12 次，每次启动前复原相同设置，测完恢复原设置。系统文件缓存预热，程序每次关闭后重新启动。

最终候选：中位数 254.776 ms，P90 271.130 ms，范围 240.273–275.675 ms。同场旧版中位数 256.542 ms；相对检查通过。前一天旧版约 198 ms 的结果来自另一次系统状态，不能把它当成本轮对照值。

这是核心可用路径的测量，不是完整解码、所有波形细节生成、声卡准备或首次扬声器出声时延。

## Windows 媒体播放器对比

Windows 11 自带媒体播放器 `Microsoft.ZuneMusic`，版本 11.2607.16.0。使用 Windows 的文件激活接口打开同一 WAV；SE 使用直接进程文件参数。共同终点是外部 UI Automation 观察到当前文件名以及可见、已启用的播放 / 暂停控件。SE 文件名取自实际窗口标题，媒体播放器取自当前媒体标题。

两边先预热，正式样本交错执行，每次均关闭程序；媒体播放器关闭窗口后，清理本次启动的后台实例，下一次重新启动。SE 每次复原同一设置，结束恢复用户设置。轮询间隔 10 ms，查询 UI 本身也有开销，结果不应理解为精确到 1 ms 的内部耗时。Windows 媒体播放器默认打开即播放；本轮 SE 打开后等待用户播放。这项比较观察界面加载，不比较首次出声，也不代表全部播放器或全部格式。

## 对比动图

首页 GIF 是另一次独立录制的两个真实打开过程：FFmpeg 60 fps 静音采集，缩放并转换为 30 fps GIF，按打开前绘制的视觉标记对齐，两边均保持 1 倍速度。对齐精度约为一个采集帧（16.7 ms）。中性背景遮住其它窗口，文件使用通用测试别名；没有分发原始音频、私人窗口或诊断内容。

录屏有额外开销，动图中的一次打开不作为上表正式样本，也没有用最快 SE 与最慢媒体播放器拼接。它展示操作过程，数值比较以上面的独立五组样本为准。
